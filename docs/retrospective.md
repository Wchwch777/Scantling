# Scantling 架构演进与技术回顾 (Engineering Retrospective)

## 1. 架构决策与设计权衡 (Design Trade-offs)

### 1.1 模块分层与领域驱动设计 (DDD)
在项目初期，我们面临两种架构选择：
* **扁平单包架构**：将数据结构、套裁算法、造价公式全放在单一 `lib/` 中。这种方式初期快，但随着清单计价规则的扩充，会导致运筹算法与财务审计逻辑强耦合。
* **分层解耦架构 (当前选型)**：
  * `core/`：保持极简，仅定义纯领域实体（Profile, Demand, Pattern, Summary），具备跨平台零依赖特征。
  * `optimizer/`：聚焦组合优化算法（FFD / Best-Fit），对具体造价财务无感知。
  * `pricing/`：基于工程造价国家规范（GB 50500），只消费 `core` 的统计指标，实现工料机分摊与敏感度分析。
  * `cmd/` & `web/`：消费层，负责交互与图谱渲染。

事实证明，分层架构使得各包职责纯粹，单元测试编写也极其清晰。

### 1.2 运筹求解算法的选型权衡
经典一维下料问题（1D-CSP）在运筹学中属于 NP-Hard 难题：
* **整数线性规划 (ILP / Simplex 列生成)**：理论最优，但求解器体积巨大，且无法直接在轻量级 WebAssembly 边缘环境中零依赖运行。
* **双策略启发式竞优 (FFD + Best-Fit)**：Scantling 选择 FFD 与 BFD 作为轻量级近似算法。当前仓库只包含小型确定性样例，尚未提供 50~200 根工程级构件的独立性能基准，因此不对现场运行时间或损耗率作实测承诺。

### 1.3 锯口物理损耗与余料价值的双重修正
许多计算机领域的 CSP 算法将母材余料视为纯废弃，这脱离了土木工程实际。Scantling 创新性引入：
1. 锯片切割损耗补偿（Kerf Width Deduction）：考虑真实机械加工损耗。
2. 余料二元分类（Reusable Remnant vs. Scrap Waste）：超过阈值的长短料按 85% 原材价冲抵成本，真实还原工程项目财务流。

## 2. MoonBit 语言工程体验

* **极速构建反馈**：`moon test` 与 `moon check` 毫秒级反馈，重构与类型纠错体验流畅。
* **清晰的模式匹配与类型安全**：不可变数据结构和严谨的类型系统保障了造价公式计算中的零浮点溢出与零空指针隐患。
* **编译目标天然契合造价工程**：造价工程师往往需要在移动端、现场平板或浏览器中实时验算，MoonBit 原生针对 WebAssembly 的优化为免安装离线使用提供了绝佳基础。
