# Scantling 架构演进与技术回顾 (Engineering Retrospective)

## 1. 架构决策与设计权衡 (Design Trade-offs)

### 1.1 模块分层与领域驱动设计 (DDD)
当前分包可以与以下结构选择比较；仓库历史本身不证明曾进行正式方案评审：
* **扁平单包架构**：将数据结构、套裁算法、造价公式全放在单一 `lib/` 中。这种方式初期快，但随着清单计价规则的扩充，会导致运筹算法与财务审计逻辑强耦合。
* **分层解耦架构 (当前选型)**：
  * `core/`：保持极简，仅定义纯领域实体（Profile, Demand, Pattern, Summary），具备跨平台零依赖特征。
  * `optimizer/`：聚焦组合优化算法（FFD / Best-Fit），对具体造价财务无感知。
  * `pricing/`：消费 `core` 的统计指标，按输入参数计算成本和假设基线。
  * `cmd/` & `web/`：消费层，负责交互与图谱渲染。

当前代码按上述包边界组织；其长期维护收益尚未经过独立比较。

### 1.2 运筹求解算法的选型权衡
经典一维下料问题（1D-CSP）在运筹学中属于 NP-Hard 难题：
* **整数规划等精确方法**：可用于求得或界定特定实例的最优解；本仓库尚未实现，也没有与精确求解器对比。
* **双策略启发式竞优 (FFD + Best-Fit)**：Scantling 选择 FFD 与 BFD 作为轻量级近似算法。当前仓库只包含小型确定性样例，尚未提供 50~200 根工程级构件的独立性能基准，因此不对现场运行时间或损耗率作实测承诺。

### 1.3 锯口物理损耗与余料价值的双重修正
当前模型包含两个可配置处理：
1. 锯片切割损耗补偿（Kerf Width Deduction）：考虑真实机械加工损耗。
2. 余料二元分类（Reusable Remnant vs. Scrap Waste）：默认以 85% 原材价为可复用余料估值假设；这不是入库、回收或现金流的实测记录。

## 2. MoonBit 语言工程体验

* **构建反馈**：本仓库运行 `moon check` 与 `moon test`；尚未建立跨机器构建时延基准。
* **数值边界**：成本公式使用 `Double`，当前测试不能证明任意输入都无溢出、无舍入误差或满足财务精度要求。
* **WebAssembly 构建**：脚本可以构建 Wasm 目标；网页当前运行独立 JavaScript 参考引擎，没有加载 Wasm。
